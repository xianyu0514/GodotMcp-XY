# 完美游戏质量天梯 v1 · 2026-09-23

> 用户目标：让 AI 可以轻松做到**完美游戏**。
> 核心立场：**"完美"不是开关，是四级天梯**——每级由"机器可测（M）"与"代理评审（A）"维度构成；
> M 项用现有基础设施（帧定时时间线/审计字段/截图）量化，A 项必须**带着截图证据被评审**，
> 永远不允许"AI 觉得行"无证据通过。声称 R4 = 全部 M 绿 + 全部 A 已评审。

## R1 可玩（Playable）— 纯 M，今天已全覆盖

| 维度 | 测法 |
| --- | --- |
| 胜负都可达 | 契约 behavior_check（FRESH 隔离） |
| 零运行时报错 | assert_no_runtime_errors / play_and_verify 默认折叠 |
| 输入已绑定 | 输入步失败自愈提示（缺 action 即点名） |
| 配置健全 | game_quality_report static 档 |

## R2 扎实（Solid）— 纯 M，时间线可测

| 维度 | 测法 | 阈值 |
| --- | --- | --- |
| **输入延迟** | 帧定时时间线：frame 0 按下，每帧采样位置；**首个位移帧序号 = 延迟帧数** | ≤ 3 物理帧（50ms@60Hz） |
| 碰撞诚实 | 走向墙的位移断言（displacement_max） | 墙前停住 |
| 进度持久 | 存档→FRESH 重启→状态还原（user:// 文件跨项） | 还原成功 |
| 性能达标 | 平台画像（desktop p1_fps 55 / mobile 30） | 全绿 |

## R3 打磨（Polished）— M + A 混合

| 维度 | 测法 | 类 |
| --- | --- | --- |
| **反馈覆盖** | 事件审计字段：每次伤害/拾取/攻击 ≥1 个 juice 响应（flash/shake/sound） | M |
| **公平性** | 每个伤害源有前摇：时间线采样"威胁出现帧→可造成伤害帧" | M，≥ 12 帧（200ms） |
| 音频在场 | 播放器/总线状态断言（bgm playing、hit sfx 触发） | M |
| 视觉一致 | 关键时刻截图（开始/战斗/死亡/胜利）由代理对照调色板与风格评审 | A（证据=截图） |
| 输赢有分量 | 死亡损失明确、胜利有高潮（代理玩后记录判断） | A |

## R4 完美（Perfect）— A 重 M 守

| 维度 | 测法 | 类 |
| --- | --- | --- |
| **前 30 秒测试** | 代理以新玩家身份用时间线脚本游玩，每 5 秒截图：能否理解操作与目标 | A（证据=截图序列） |
| 反馈密度 | 有响应事件 / 总事件 ≥ 1.0 | M |
| 平衡性 | 多局游玩记录：无支配策略、难度曲线合理 | A |
| **零已知缺口** | 天梯全部条目要么绿、要么显式豁免并注明理由 | 守门 |

## 执行规则（make_game_perfect 配方即此引擎）

1. **逐级攀登，不许跳级**：R1 红时修 R1，不看 R3。
2. **最小修复循环**：每个缺口一次只改一个旋钮 → verify_change_effect 证明生效 → 只复验受影响条目。
3. **A 项的证据纪律**：截图/轨迹随判断落档；无证据的"好"按未评审计。
4. **诚实的停止规则**：达到 R4 = 完美；否则输出"距完美还差哪些条目"的精确清单——
   把"追求完美"变成有限步骤，而不是无限打磨。

## 与既有系统的关系

- R1/R2 全部复用现有工具（契约/时间线/审计/画像）——**零新工具**（宪章 K 原则）。
- 延迟与公平性的"每帧采样测帧数"是新教法，但用的是既有时间线能力。
- 本文档是标准；`make_game_perfect` 配方（第 26 个）是执行引擎；两处同步演进。
