# godot-ai 经验吸收计划

日期：2026-09-07。目标：减少 AI 使用 Godot 时的人工排错和失败恢复成本。

基于本地 `cdf3f07`，对照 [godot-ai 工具契约](https://github.com/hi-godot/godot-ai/blob/main/docs/TOOLS.md)、[脚本处理器](https://github.com/hi-godot/godot-ai/blob/main/plugin/addons/godot_ai/handlers/script_handler.gd)、[项目运行处理器](https://github.com/hi-godot/godot-ai/blob/main/plugin/addons/godot_ai/handlers/project_handler.gd) 与 [批量处理器](https://github.com/hi-godot/godot-ai/blob/main/plugin/addons/godot_ai/handlers/batch_handler.gd) 的公开行为进行独立实现。保留当前原生 GDScript 架构和现有 MCP 工具名。

## 价值选择与执行顺序

| 优先级 | 已确认的问题 | 本次改进 | 验收证据 |
| --- | --- | --- | --- |
| P0 | 脚本保存成功后没有同次编译反馈 | `create_script` / `modify_script` 增加每次写入的诊断；C# 与项目脚本模板明确标识未检查，保留原有 validate 开关与 validation 摘要 | 正确/错误脚本、真实错误行号、修改后修复、相对依赖、已缓存脚本和 C# 测试；真实编辑器回归 |
| P0 | 重用运行会话早退，未核实探针；停止阻塞主线程且超时报成功 | 统一新启动/复用状态判断；停止可重复调用、按帧等待并报告超时 | 调试连接/探针/暂停/过期会话、启动超时、切换失败、异步停止测试；独立 HTTP 集成 |
| P1 | 批次预检失败会遗留节点；删除撤销用复制体而重做指向原体 | 结构操作无分配预检；扩展操作失败释放临时节点，保持原节点身份，用 UndoRedo 管理节点引用和子树 owner，反向恢复操作 | 失败零修改、冲突、两轮 undo/redo、owner/兄弟顺序和清空历史释放测试；真实 EditorUndoRedo 集成 |

## 本次不纳入

- 客户端自动配置、自更新、多编辑器管理：对当前个人开发流程收益较低，且引入独立配置/分发维护面。
- Python 服务和进程生命周期：与原生架构不匹配。
- 通用大批处理调度器和新的工具别名：现有能力重叠高，本次先修真实故障。

## 兼容性与边界

- 最终集成基线为主分支 `3ed08d3`，其工具总数为 232（28 core、198 supplementary、6 meta），本次不增加工具。最初对比的本地版本有 226 个工具。新增返回字段和可选参数，不删除既有接口。
- 文件写入成功与编译通过是两个不同结果；诊断失败不会撤销已经明确请求保存的源码。编译依赖仍遵循 Godot 的缓存规则，不能替代依赖修改后的完整验证或实际运行。
- 启动状态反映当下能取得的运行证据，不代表游戏玩法正确。
- 批量操作先按请求前的场景解析路径，再检查模拟层级中的冲突。任意用户 `@tool` 回调、外部副作用与崩溃恢复不在事务保证内。
- 先以真实旧行为得到失败测试，再实施；通过针对性检查后，执行导入门禁和受影响模块检查，避免逐项重复全量测试。

## 成功标准

同一次脚本写入能够告诉 AI 该看哪条错误；运行状态不把尚未就绪当成可游玩；批量修改可以可靠撤销和重做。最终测试结果记录于 PR 或交付说明，不能用工具路由命中率替代端到端成功率。

## 执行结果

- 已将改进集成到主分支 `3ed08d3`，保留上游 `modify_script.validation` / `validate: false`、启动早期退出检查，以及批量属性/脚本/信号编辑和保存能力。
- Godot 4.7 导入检查通过，无脚本解析或加载错误。
- 45 个受影响测试文件：1046 项通过，0 失败；2 项已有场景测试在 headless 环境没有执行断言，GUT 标记为 risky/pending，未计作通过。
- 独立编辑器验证：脚本诊断 14 项；批量恢复 55 项（含扩展操作和实际保存）；运行生命周期通过 19 次真实 HTTP 调用。
- 工具目录保持 232 个。JSON/CSV 翻译、Schema、工作流和编译缓存关联检查通过。

后续优先用真实游戏任务记录成功率、人工介入次数和恢复耗时；出现重复故障再扩展功能。无需以学完或移植 godot-ai 的所有功能作为目标。
