# 最高收益实施：可靠修改已有项目

基线：主分支 `196ae50`（PR #117 合并后），2026-09-08。

## 价值判断

这轮先修已有项目修改的破坏风险。旧实现把越界行号当成全文件替换，且不能判断 AI 读取以后发生的手工修改。继续增加工具数量或游戏模板不会解决这些问题。

本轮实现：保留原有 `modify_script` 接口，增加唯一文本片段替换、可选内容指纹检查、未保存目标缓冲区检查；错误请求保留文件，编译失败后可以用新指纹继续修复。工具数保持 232。

## 实施与验证顺序

1. 先在旧实现上复现破坏性越界行为、过期覆盖和新编辑契约失败。
2. 实现参数校验、内容指纹和精确片段替换；保持现有全量/行编辑兼容。
3. 加入目标编辑器缓冲区检查，在 API 不可用时明确报告能力缺失。
4. 通过同一隔离编辑器的 HTTP 接口回放 12 项修改/恢复任务，用文件字节检查实际结果。
5. 用独立 Godot 运行进程检查修改后的行为；检查诊断、编译缓存、工具 Schema、翻译和工作流兼容性。
6. 同步文档，清理临时文件，提交分支并创建 PR。

## 可重复的 12 项回放

运行 `python test/integration/test_script_edit_safety_flow.py`，可用 `GODOT_EXE` 指定引擎。测试复用一个隔离编辑器，自动选择回环端口，不修改正在使用的项目。

| 场景 | 独立验收条件 |
| --- | --- |
| 修改移动速度 | 保留注释和其余代码；运行时速度为 250 |
| 修改输入动作 | 仅替换目标字符串；运行时动作名正确 |
| 扩充保存数据 | 保留原 score，运行时新增 health |
| 删除废弃调试函数 | 精确移除多行函数，其余字节不变 |
| 保留读取后的手工改动 | 等长文件修改也触发冲突，文件不变 |
| 保留未保存的编辑器修改 | 拒绝写入，磁盘与 CodeEdit 缓冲区均保留；无 API 标记 unsupported |
| 拒绝歧义片段 | 重复片段不产生修改 |
| 拒绝越界行号 | 文件不被截断或替换 |
| 冲突后重新应用 | 重新读取后仅更新目标值，保留新手工字段 |
| 编译失败后修复 | 先收到实际编译错误，再使用新指纹修复并在独立进程执行 |
| 片段缺失后恢复 | 第一次零修改，重新读取后正确替换 |
| 旧接口与 CRLF | 原行编辑和全量替换仍可用，未修改部分换行保留 |

报告位于测试临时目录的 `report.json` 与 `http_evidence.json`，记录引擎版本、测试文件指纹、场景结果、耗时、调用数和请求/响应。独立运行检查完成前，总状态为 incomplete。缺少引擎 API 的场景计为 unsupported，不能算通过。

这些是固定调用顺序的工具回归任务。它们不测模型规划、真实输入游玩、完整存档持久化或多文件崩溃恢复；没有运行 godot-ai，也没有模型调用，所以报告中 AI 成功率和竞品成绩为 null。

## 下一阶段的比较门槛

此前建议的 4 项新建游戏任务、4 项已有项目修改、4 项故障恢复，仍需要相同模型、引擎、初始项目、预算和独立验收的实际代理运行。此次先落实其中共同依赖的脚本修改可靠性及回归基础。只有完成受控对比，才能用成功率、人工介入、耗时和每次成功成本讨论是否超越 godot-ai。

## 验证结果

- 旧实现上第一组 16 项测试有 14 项失败、2 项通过；包含实际文件被覆盖的断言失败。新增缓冲区守卫与 Windows 路径边界均先见失败，再实现修复。
- Godot 4.7：8 个受影响测试文件共 177 个不同测试通过、0 失败（第一次关联运行 175 项，新增 2 项后重跑直接测试 19 项）。
- 隔离编辑器 HTTP：12/12 修改与恢复任务通过，0 unsupported，22 次工具调用。
- 独立 Godot 运行进程：移动速度、输入动作、保存数据结构、修复脚本执行共 4 项检查通过。
- Godot 4.7 导入检查通过，无脚本解析/加载错误；JSON/CSV 描述同步且工具总数未变。
- 单文件内容前置检查不提供多文件事务；没有传入 hash 的旧请求继续保持旧的整文件替换语义。Godot 4.6 无缓冲区检查 API 时明确降级。
