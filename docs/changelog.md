# Changelog

All notable user-facing changes are tracked here.

## Unreleased

- Workflow reliability (stress-test findings): tool evidence no longer misjudges real successes — `manage_localization` results carrying an explicit `success: true` pass without a status word, and mutation completions such as `created`/`saved`/`written`/`unchanged`/`recovered` are accepted by the generic verdict instead of triggering repair/replan. Successful creation steps (scene/script/theme/tileset/animation, test directory, smoke test) register a workflow artifact registry, and the runner resolves `$scene`-style references and auto-derives schema-required `script_path`/`scene_path`/`tileset_path`/`theme_path`/`animation_name` inputs from it, so `create_script → attach_script`-style chains no longer stall on `needs_input`. Objective-gate steps support negative testing via the new `expect_fail` plan option (`{"verify_scripts": true}` inverts that gate's verdict), enabling fault-injection loops that must prove a detector fails. Negated intent is respected: “Android 不适用” / “3D not applicable” no longer selects the android platform or adds the glTF inspection gate. `run_project` is idempotent — re-running the live scene (or omitting `scene_path`) reuses the session instead of erroring on “already running”, while a different scene switches sessions deterministically; plan-authorized `run_project`/`stop_project` auto-pass the interactive window policy. TileMapLayer cell tools name the active scene in node-not-found errors so editor-context drift is immediately actionable. No new tools were added.
- QA Bootstrap for game workflows: `prepare_project_test_environment` inspects `res://test/`, `res://tests/` and `res://.mcp_runtime_tests/` and returns `ready`/`empty`/`unconfigured`/`blocked` with a `recoverable` flag and recommended action. `ensure_project_directory` safely and idempotently creates `res://` directories, and `create_project_smoke_test` writes a framework-independent native smoke test so an empty project can pass QA without GUT or Python. `list_project_tests` now reports a missing directory as a recoverable `unconfigured` state instead of a fatal error. The `quality_assurance` workflow profile bootstraps the environment first (prepare → ensure directory → discover ≥1 test, auto-creating a smoke test when empty → verify scripts → run tests), so a fresh prototype no longer stops at `replan_required` when `res://test/` does not exist. Catalog: 226 tools (28 core, 192 advanced, 6 meta).
- Fixed the persistent Quick Tunnel startup regression: a detached headless supervisor now preserves the previously reliable stdout/stderr URL capture path while surviving editor shutdown, mirrors output into the project-scoped durable log, selects HTTP/2 for QUIC-blocked networks, and replaces failed or 20-second-stalled pre-URL children for up to three attempts. Once a URL is published it has no startup deadline and stops only on an explicit user request or process/computer exit. The panel's 30-second threshold is now a non-destructive slow warning instead of killing a live tunnel. Windows PATH reuse is normalized to remove mixed `\\/` separators, and DNS, proxy, TLS, rate-limit, timeout and Cloudflare-service failures receive localized actionable status text.
- The persistent-tunnel panel now keeps its status text synchronized with the selected UI language, paints visible local-cache and download-progress stages, automatically switches a stalled or unusually slow cloudflared download to the next verified source, warns when Quick Tunnel URL discovery exceeds 30 seconds without killing the process, supports cancelling an in-progress download with **Stop tunnel**, and immediately records source attempts, process launch, restore, slow-start and exit diagnostics in `mcp_server.log` instead of appearing to wait indefinitely.
- User-started Cloudflare Quick Tunnels now survive project reloads, plugin reloads and full Godot shutdown. The manager launches `cloudflared` as an independent process with a durable project-scoped log and session record, restores the same PID and public URL when the project reopens, prevents duplicate tunnel launches, validates the process command line before adopting or stopping a saved PID, and clears stale state after computer shutdown. Only the panel's explicit **Stop tunnel** action terminates a live managed tunnel.
- Cloudflare Quick Tunnel setup is now local-first across projects. The panel checks an always-visible manual override, the editor process `PATH`, a machine-local shared cache, and checksum-valid legacy `user://cloudflared` caches (including sibling Godot projects) before making any network request. Verified legacy files are copied atomically without deleting the original, managed macOS archives are rechecked on reuse, and only one shared download is needed per OS user, pinned version and platform architecture.
- Complete-game execution is now adaptive instead of functionally capped. Default checkpoint slices grow through 4/8/16/32 calls and a positive `max_steps` affects only the current call; a 100-capability regression proves every explicit requirement survives, executes and reaches evidence-gated completion without adding visible schemas. Unfamiliar composite goals can merge schema-free clause routes beyond ten capabilities, while uncovered requirements return clarification instead of false completion. Async work never blocks merely because it exceeded a poll count, identical receipts aggregate, distinct evidence is retained, transient failures return exponential backoff guidance, and repeated identical verification/repair failures request a different plan. On restart, audited reads and idempotent operations replay safely while uncertain mutations fail closed. Default responses expose only a four-step ready projection and counters rather than repeating the DAG, arguments, receipts or schemas.
- Added `plan_game_workflow` and `run_game_workflow`, bringing the catalog to 223 tools (28 core, 189 advanced, 6 meta). The deterministic compiler composes 12 reusable production profiles into a persistent goal DAG that can exceed the 8/10 ad-hoc discovery budget. Distinct same-tool writes retain separate profile/step identities; repeated reads reuse normal caches. Missing fields return the current atomic input Schema on demand without loading the catalog. Async polling, compare-and-swap IDs, protected paths and exact blueprint integrity prevent runaway or stale execution. Unknown goals and missing capabilities block explicitly, and `completed` requires engine-issued evidence for every objective gate. Gates cover 25 bilingual goals with 100% declared profile/capability recall, compilation P95 below 5 ms, plus a multi-round gameplay + UI + QA completion loop.
- Workflow routing now uses precomputed atomic-name signatures, bilingual intent aliases, direct action/object evidence, rare-term weighting and read-family matching before its cost-aware fallback. A deterministic gate covers 48 real English/Chinese game-production tasks across 12 domains and 174 required atomic-tool groups: Recall@8 and complete-task success are 100%, verification-stage recall is 97.30%, known cross-domain distractors are 0, and average supplementary-schema savings are 97.34%. The default budget remains 8, every atomic tool remains exactly addressable and no tool, schema, model call or network dependency was added.
- High-volume read pagination is now lossless and compute-aware. `list_project_resources`, debugger stack frames/variables, reverse-resource scans and migration/deprecation scans expose common continuation metadata (`returned_count`, `has_more`, `next_offset`); stable project scans reuse one dependency-revisioned full snapshot across page views instead of rescanning. Snapshot retention is bounded to 8 entries and 4 MiB each. Stateful `apply_migration_fixes` is intentionally not re-executed for pagination, so functionality and consistent mutation semantics remain ahead of token/latency savings. This change added no tool.
- Large successful tool results are now cheap up front without becoming lossy: the existing head/tail preview includes a standard MCP `resource_link`, and `resources/read` serves the exact JSON in deterministic UTF-8-safe 16 KiB pages addressed by SHA-256. Identical payloads reuse verified spill files, dynamic links do not bloat `resources/list`, errors and source/log readers remain complete inline, and spill failures fall back to the complete inline response. A 204 KiB Unicode regression fixture verifies 95.62% fewer initial bytes and exact 13-page reconstruction.
- `set_dod` now rejects whitespace-only criterion text on the single-criterion path (both creating a new criterion by text and renaming an existing one by index), returning an error instead of persisting an empty-text criterion. This matches the non-empty rule already enforced on the full-list / `add_task` path.
- Made DoD criterion text consistently trimmed on every storage path. `set_dod` now stores the trimmed `criterion` (matching how criteria are matched and created), and `_normalize_dod` (used by `add_task` and full-list `set_dod`) now trims string entries and rejects whitespace-only ones, the same as dict entries. Previously a `criterion` passed with surrounding whitespace (e.g. `"  fps ok  "`) could be persisted with padding yet matched trimmed, causing lookups to miss and duplicate entries to appear.
- Performance: cut redundant work on the per-request hot path without changing any behavior. The script sandbox (`execute_script` / `execute_editor_script` / `evaluate_*` guard) now compiles each denylist RegEx once and reuses it from a process-lifetime cache instead of recompiling ~26 patterns on every scan, and strips string/comment content with an O(n) buffer join instead of O(n²) per-character concatenation. The JSON-RPC server no longer builds full-request/response `JSON.stringify` strings for debug logging when the log level is above DEBUG (the default), so every `tools/list`, `tools/call`, `resources/list`, and incoming message skips that wasted serialization.
- Made `set_dod` single-criterion updates transactional: the new-criterion path validates all error conditions (invalid gate, `observed` without a gate, non-dict `observed`) before appending, and the existing-criterion path mutates a copy that is only committed once every check passes. A failed call no longer leaves a half-created criterion or a partially-modified one (e.g. a gate attached but the subsequent `observed` evaluation rejected) in the task's DoD.
- Hardened node-creation type validation in `create_node` and `batch_scene_node_edits` create ops: they now reject non-Node classes (e.g. `Resource`, `RefCounted`) and abstract Node classes (e.g. `CanvasItem`) up front with a clear, actionable error instead of letting `ClassDB.instantiate` return null and crashing on the subsequent property assignment. The check is a pure `ClassDB`-only helper (`class_exists` → Node-derived → instantiable), so it's deterministic and unit-tested. Concrete Node types are unaffected.
- Tightened `manage_task_plan` DoD gate evaluation: `set_dod` now evaluates `observed` against the gate even when it creates a brand-new criterion by `criterion` text (previously the metrics were silently ignored and `met` defaulted to false on that path), and an invalid gate no longer leaves a half-created criterion behind. A `no_runtime_errors` gate now requires an actual measurement — an empty `observed` is treated as "can't prove ⇒ not met" instead of passing on a default of 0, matching the other gate types. Also refreshed the `manage_task_plan` tool description in the translation files and documented the optional `gate`/`last_evaluation` DoD fields in the persisted schema.
- Closed a script-sandbox bypass and reduced false positives: `execute_script`'s single-line Expression path is now scanned by the same guard (previously only the multi-line/`execute_editor_script` path was), so a single-line `OS.execute(...)` can no longer slip through under STRICT security. The filesystem check no longer flags Godot scene-tree node paths (`/root/...`) and only treats `~`/`~/` as a home-dir path instead of matching any string containing a tilde (e.g. `"~5 enemies"`); out-of-project absolute and system paths (`/etc/`, `/var/`, drive letters, `~/...`) stay blocked.
- Hardened `manage_task_plan` Definition-of-Done with optional machine-checkable `gate`s so the VERIFY phase decides `met` objectively instead of self-asserting. A DoD criterion can declare a gate of type `performance_budget` (a `budget` of min_fps/max_frame_time_ms/max_physics_frame_time_ms/max_object_count/max_resource_count/max_rendered_objects/max_memory_mb/max_node_count, mirroring `assert_performance_budget`), `no_runtime_errors` (`max_errors`, default 0), or `visual_baseline` (`max_diff_pixels`/`max_diff_ratio`). On `set_dod`, passing `observed` measured metrics auto-computes `met` from the gate and records the verdict as evidence. No new MCP tool; this deepens an existing one and the catalog stays at 215 tools.
- Added a script sandbox guard for `execute_editor_script`, `evaluate_debug_expression` and `evaluate_runtime_expression`: under STRICT `security_level` (the default), scripts/expressions are scanned by a configurable capability denylist (OS process execution, out-of-project filesystem paths, networking, other dangerous APIs) and rejected with a structured `blocked` result before execution. PERMISSIVE mode keeps the previous unrestricted behavior. No new MCP tool is added; the guard hardens existing tools and the catalog stays at 215 tools.
- Expanded the MCP tool catalog to 215 tools by adding the ship-loop closure and localization tools.
- Added `smoke_test_export` (Editor-Advanced): post-export smoke test that resolves the artifact, optionally exports first, asserts the product file exists, and launches it to capture and check the exit code — an objective, runnable-build gate.
- Added `bump_version` (Project-Advanced): semantic version bump written back to project.godot plus an automatic dated changelog entry, with a `dry_run` mode.
- Added `manage_localization` (Project-Advanced): single action-based localization workflow — `list` registered `.translation` files, `extract` translatable keys from scenes/scripts into a Godot CSV (preserving existing translations), `import` that CSV into per-locale `.translation` files registered in ProjectSettings, and `export` registered translations back to CSV for round-trip checks. All write actions support `dry_run`.
- Added external-generation budget guards: `generate_asset` and `generate_3d_asset` external calls now honor a configurable call-count/limit window (`external_gen_budget`, `external_gen_budget_window_sec`) and reject calls over budget. Default 0 keeps it unlimited and backward-compatible.
- Added a minimal GitHub Actions CI workflow (headless import + GUT unit tests).
- Refined and normalized the documentation set: root README, Chinese README, addon README files, configuration, architecture, testing, contributing, remote access, industrialization guides and generated tool-reference pages.
- Repaired corrupted Chinese documentation text in repository-facing docs and agent skill guides.
- Clarified the 215-tool model: 30 core tools, 183 advanced tools and 2 always-on meta tools.
- Security hardening (Phase 0): the HTTP transport now binds to `127.0.0.1` by default (`allow_remote` must be explicitly enabled to bind all interfaces), the CORS origin defaults to empty (no CORS header), JSON-RPC batch payloads return `-32600` instead of crashing, and connections are capped. `execute_script` / `execute_editor_script` were downgraded from core to supplementary (disabled by default) to shrink the default remote-code-execution surface; `generate_asset` / `generate_3d_asset` now validate endpoints (https + host allowlist) and API-key environment variables. Tool counts updated accordingly: 28 core + 185 advanced + 2 meta = 215.
- Protocol compliance (Phase 0): `ping` is now handled, notifications never receive responses, rate limiting skips notifications, and `tools/list` / `resources/list` / `prompts/list` responses include `_meta.ttlMs` / `cacheScope` (required by current MCP clients). `serverInfo.version` and the HTTP info endpoint now read the real plugin version from `plugin.cfg`. Auth can now be toggled at runtime (auth manager is rebuilt on server start from current settings). `get_editor_logs` no longer depends on translated UI panel names and falls back to the versioned editor log file and `user://logs/godot.log` script-error lines. `validate_script` now returns structured compile errors with line numbers extracted from the compiler output.
