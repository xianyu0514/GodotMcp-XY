# 门槛 B：真实多系统纵向切片 — 实施规划

状态：规划（2026-09-20）。来源：大型 2D 审计（2026-09-19）第 B 道投入门槛，前序四步交付与门槛 A/C 已完成。

## 目标（审计原文口径）

一个 20–30 分钟的真实游戏切片，作为"这套 MCP 能安全承载大型项目持续开发"的实证。要素：

- 至少三个**独立地图**（真实场景文件，非单控制器生成物）
- 战斗或交互、**物品**、**任务**、**UI**、**保存**与**场景切换**
- 资源有实际视觉/音频内容；压力场景与普通游玩场景分开
- 通过 MCP 连续完成八类修改（共享敌人调参 → 保留 Boss 特例 → 新增道具属性 →
  更新任务奖励 → 重命名资源 → 调整一张地图 → 修复测试 → 导出），
  **每次不相关的手工内容保持不变**

## 结构决策

1. **真实模块化项目**（区别于代表游戏/样板的单控制器蓝图）：`slice_b/` 下的独立项目树，
   模块边界 = 目录边界（maps/ items/ quests/ ui/ save/ combat/），共享敌人与 Boss
   是不同的 Resource/Scene。MCP 不再生成控制器，而是**理解、修改、验证**真实资产。
2. **版本化存档演进（P2 同步落地）**：save 系统带 schema_version + 迁移链 +
   备份；跨地图部分进度保存；损坏存档回退备份。存档是可复用游戏模块
   （`slice_b/save/`），MCP 提供检查/迁移/验证工具调用。
3. **验证走已建好的主线**：影响分析（query_change_impact）决定每次修改的
   触碰面；变更单（apply_change_set）执行跨文件修改（含读版本绑定与中断恢复）；
   验证队列（run_verification_queue）分片收证据；TileMapLayer 运行验证覆盖地图。
4. **八类修改是验收剧本**：每步产出证据（变更单回执 + 队列判定 + 不相关文件
   锚点 hash 不变），一个集成测试脚本固化重放。

## 里程碑

| # | 交付 | 验收 |
|---|---|---|
| M1 | 项目骨架 + 三地图场景（TileMapLayer）+ 场景切换 + 玩家移动 | 三地图往返切换无报错；每张地图有独立布局与音乐/静音差异 |
| M2 | 共享敌人 + Boss 特例 + 战斗（接触伤害/击退/生命） | 改共享敌人属性，Boss 特例不被覆盖（变更单证据） |
| M3 | 物品 + 背包 + 任务（拾取→提交→奖励） | 新增道具属性、更新任务奖励各走一次变更单 |
| M4 | UI（HUD：生命/金币/任务提示）+ 版本化存档 v1 | 存档跨地图记录部分进度；schema_version 与备份就位 |
| M5 | 存档 v2 + 迁移链 + 损坏回退（P2 交付） | v1 存档经迁移在 v2 正常；损坏存档回退备份继续 |
| M6 | 八类修改剧本固化（集成测试）+ 导出冒烟 | 全链 MCP 驱动；不相关内容锚点不变；导出包可启动 |

每个里程碑：GUT 单测（模块逻辑）+ 集成证据（MCP 驱动步骤），提交在
`devin/*-slice-b` 分支，复用 CI 的 [rep-ci] 通道。

## 边界与不做

- 不做无缝世界/联网/主机平台（审计明确另设门槛）
- 不把游戏系统塞进蓝图生成器（审计 §三.3 的方向性约束）
- MCP 服务器不变成游戏运行框架：save/combat/quest 是游戏代码，
  MCP 只负责理解/修改/验证
