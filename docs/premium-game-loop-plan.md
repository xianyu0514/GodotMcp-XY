## 2. 阶段计划（每阶段带可执行验收门）

### Q0 — 补完测量闭环（1-2 日）
1. 墙碰撞 oracle（StaticBody2D 建墙 + 位移断言不穿透）进 self_agent oracle_n1；
2. E4/R3 自校准（复用 self_agent.py，换目标与 oracle）；
3. **正式 12×3 对照**（第一方模型 vs 确定性基线，预算按校准值固定）。
**验收**：首份完整报告（12 任务×通过率/错误完成声明/人工介入），oracle 自证通过，失败样本全保留。

### Q1 — 累积性（2-3 日）
1. create_scene 派生：工件已有场景时**默认在既有场景上叠加**（不覆盖），越界改动进 journal 冲突检查；
2. 账本重验：新目标完成时对账本内最近 N 个目标重跑其行为套件（同场景、script 重挂），结果进完成报告；
3. 多场景骨架：标题/关卡/HUD 分场景 + 切换断言（探针 current_scene 变迁）。
**验收**：5+ 目标会话产出单一累积游戏，既往目标套件仍绿（回归账本生效）。

### Q2 — 内容深度（3-5 日）
1. 关卡布局动词：平台跳跃布局（多平台 + 高度差 + 出生点），布局可断言（可达性：从出生点到金币的路径位移）；
2. 多实体：多金币（计数 N）、多敌人（巡逻带不重叠——复用布局求解器）；
3. 进度/难度：关卡递进（难度参数随关数变化）+ 平衡预算（死亡数/通关时间区间断言）。
**验收**："做 3 个关卡的平台跳跃游戏"一句话产出可玩多关卡，平衡断言通过。

### Q3 — 视觉精品（3-4 日）
1. **金标准循环运转**：bootstrap → 人工批准（`update_baseline=true` 即批准动作）→ 此后回归强制；面板加"待批准"提示；
2. 程序化 juice：粒子（拾取迸发）、渐变背景、震屏（死亡）——全部零资产、行为可断言（粒子发射数/震屏偏移）；
3. 资产管线：generate_asset 密钥配置文档化 + 导入验证门禁接入 profile。
**验收**：视觉金标准被人工批准过一次并拦下至少一次回归；juice 断言在真机通过。

### Q4 — 迭代广度（2-3 日）
1. 可调参数表：SPEED/JUMP/磁吸半径/敌速/难度——`parse_tuning_goal` 扩为参数+方向；
2. 迭代对比通用化：任意参数的"调前/调后"可观测指标映射表；
3. 自动平衡循环：平衡预算未达 → 自动调参 → 重验（有界次数，不无限）。
**验收**："让难度降低一点"类目标走完调→验循环且指标朝请求方向变化。

### Q5 — 3D 最小（2-3 日）
N4 原生证据：CharacterBody3D + 地面 + 相机 + Area3D 金币 + 位移/拾取断言（复用 2D 全部机制）。
**验收**：3D 移动收集目标真机全绿。

### Q6 — 长稳与分发（2-3 日）
1. soak：长会话内存/帧率趋势门禁；
2. 导出矩阵：Windows/Web 预设 + 导出冒烟进交付链；
3. 安装矩阵复跑（干净环境/升级/回退）。
**验收**：soak 无泄漏趋势；双平台导出冒烟绿。
