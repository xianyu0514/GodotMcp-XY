# AI 能力发挥规范（Capability Charter）v1 · 2026-09-22

> 来源：与用户的三轮设计辩论定稿——"约束不能限制 AI 的脑子"、"AI 不需要具体知识（知识应沉入环境）"。
> 地位：与"零假完成"不变量同级，**所有里程碑与配方/工具交付的验收前提**。
> 每条标注执行机制：【门禁】自动测试强制（CI 即失败）；【审查】提交前人工核对项；【沉淀】文档义务。

---

## 一、约束边界——约束"完成声明"，绝不约束"思考路径"

| # | 规则 | 执行 |
| --- | --- | --- |
| C-1 | 门禁只能挂在**声称完成**的时刻（契约验收、发布冒烟），探索与尝试零审批。禁止任何"执行前必须先跑 X"的预置步骤要求。 | 审查 |
| C-2 | 契约只声明**什么必须为真**（requirements），禁止规定**怎么做到**（步骤序列不得成为完成条件的一部分）。 | 审查（契约示例审查） |
| C-3 | 配方是**默认不是围墙**：任何配方域必须存在逃生门——exact-name 工具直达、L3 通用循环（make_any_game）。新增配方必须说明"不走本配方的路径是什么"。 | 审查 |
| C-4 | 工具面全量可达：路由是省 token 的捷径，不是准入许可（发现预算 ≠ 能力天花板）。既有测试已锁（router coverage=1.0）。 | 门禁（既有） |
| C-5 | 探索性调用（读、量、截图、dry_run）永不计入"破坏性"语义；只有写与声称完成才需要守卫。 | 审查 |
| C-6 | **声明式而非命令式（2026-09-23 增补，用户定向）**：入口面（make_any_game、godot://capabilities）必须是能力卡——"可以做什么/可以测什么/什么算证明/什么恒真"，绝不规定步骤顺序与方案。参照配方是可选知识，永不强制；命令式表述视为软限制债，逐步迁移。 | 审查 |

## 二、知识分层——什么允许出现在提示词里

判定四分法（K-0，总则）：**通用常识不喂；项目事实不写死；环境意外优先工具化；设计价值观可内联。**

| # | 规则 | 执行 |
| --- | --- | --- |
| K-1 | **通用常识禁止**进入配方正文。判定：Godot 官方文档一页内可查、任何 Godot 项目通用的表述（如"信号可以解耦节点"）。出现即删——它只烧上下文。 | 审查（季度审计） |
| K-2 | **项目事实禁止写死**：不得断言用户项目的结构（既有场景路径、节点名、目录布局）。既有场景引用必须 `<占位符>` 化；新文件的创建路径可以给默认值，但必须(a)以动词 Create/生成 语境出现、(b)可被调用方覆盖、(c)不得与仓库自身项目耦合。 | **门禁（本提交新增）**：配方渲染文本(a)不得出现仓库内部项目名（slice_b / stress_game / TestScene / res://addons/godot_mcp）;(b)所有 `.tscn` 引用必须在 `<...>` 占位符内。 |
| K-3 | **环境意外优先工具化**：新增任何"操作真理"（环境与预期的静默偏差）必须先回答"为什么不能是工具的检测分支？"——只有无法自披露的才允许留在文本。文本真理必须在 playbook 有对应条目（沉淀义务）。 | 审查 + 沉淀 |
| K-4 | **设计价值观允许内联**：不可测量的判断（"无前摇=不可闪避=缺陷"、"会静默跳过的效果就是缺陷"）——没有工具能替你持有价值观。 | 沉淀 |
| K-5 | **过期条款**：凡指向具体插件行为的真理，若该行为在插件中修复，真理必须改写为检测（沉入工具）或删除；禁止留下描述已修复缺陷的"僵尸知识"误导后续会话。 | 审查（随修复同步） |

## 三、环境自披露——工具是知识的归宿

| # | 规则 | 执行 |
| --- | --- | --- |
| S-1 | 每个静默陷阱必须有检测器：命名陷阱 + 给出**可粘贴的下一步精确调用**（needs 模式，参照 verify_change_effect）。 | 审查（新工具出厂项） |
| S-2 | 错误消息必须自愈：错误文本内嵌精确的修复调用（参照 "Tool is disabled" 的做法），禁止只报现象。 | 审查 |
| S-3 | 测量必须免疫延迟：引擎侧时间戳/帧步进；陈旧缓存值不得当作测量值（stale 必须显式拒绝——位移断言已有该语义，任何新测量工具沿用）。 | 审查（新工具出厂项） |
| S-4 | 诚实降级：检测能力不可用时返回 unavailable，不得当作通过（unsaved-buffer 检查先例）。 | 审查 |

## 四、诚实契约——既有不变量，编号重申

| # | 规则 | 执行 |
| --- | --- | --- |
| H-1 | 零断言通过 = 冒烟，strict 契约拒绝其充当功能完成证据。 | 门禁（既有） |
| H-2 | 任何必需项缺验证证据 => overall=incomplete，且点名缺项。 | 门禁（既有） |
| H-3 | behavior_check 项 FRESH 运行隔离、自我完备（需要目标状态就自己造）。 | 门禁（既有） |
| H-4 | 收尾报告逐项引用清单，未验证项禁止写成完成。 | 审查（AGENTS 已强制） |

## 五、默认值——把"需要技巧做对"变成"不做才是特例"

| # | 规则 | 执行 |
| --- | --- | --- |
| D-1 | 新手第一坑应成为默认行为（attach_script 外部引用、震屏自动建相机先例）；旧行为保留显式 opt-out。 | 审查（修复时核对） |
| D-2 | 破坏性批量默认 dry_run 预览；创建类操作默认幂等（on_exists=skip）；跨文件改写带旧值守卫（expect_current 先例）。 | 门禁（工具单测断言默认值） |

## 六、上下文经济——注意力花在游戏上，不花在管道上

| # | 规则 | 执行 |
| --- | --- | --- |
| E-1 | 工具 schema 超 400 token 须登记 KNOWN_OVER_BUDGET_TOOLS 并注明原因；描述精简列为独立工作项。 | 门禁（既有） |
| E-2 | 答案同行：证据/失败原因/修复调用内嵌响应，调用方不得为了拿到结果再去挖文件。 | 审查 |
| E-3 | 知识注入是权宜：每次向配方添加文本真理时，同提交必须评估"能否下沉为工具检测"；不能时在 playbook 说明原因。 | 审查 + 沉淀 |

## 例外流程

任何规则的不适用必须在**提交信息中显式声明**违反的条款 + 理由 + 补偿措施，并在下个相关包复审。无声违反按漂移处理（工作流纪律失职）。
