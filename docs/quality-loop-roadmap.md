# AI 完整优质游戏闭环 — 实施规划

制定日期：2026-09-13。基线：main = #127（fb04122）。本文档是"一句话 → AI 制作优质游戏"闭环的唯一执行规划，后续实施按阶段推进并随实测修订。

---

## 0. 定位与算力哲学

**目标**：用户用一句自然语言描述游戏目标，AI 在真实 Godot 项目中完成"理解 → 规划 → 构建 → 验证 → 迭代 → 打磨 → 交付"的完整闭环；完成判定永远基于**真机行为证据**，而非工具自述。

**算力原则（本规划的核心约束）**：

1. **不设固定上限**。任何阶段都不以"预算耗尽"为由停止追求质量——预算耗尽不是失败模式，浪费才是。
2. **算力投放的唯一判据是边际证据价值**：一份算力只有满足以下之一才值得花——
   - 产出能改变决策的证据（发现缺陷、证明行为、定位瓶颈）；
   - 关闭一个验证门禁（让"未验证"变成"已验证"）；
   - 扩大能力覆盖（新动词/新门禁/新场景类型）。
3. **防浪费靠机制，不靠限额**（详见第 4 节）：分层验证阶梯、确定性回放优先、证据缓存、durable 回执防重放、校准先行、失败驱动重试。这些机制保证每一份算力都在产生信息，而不是限制总量。
4. **经验事实**：截至本规划日，最高收益的算力投放是**每片改动的真机 durable E2E**——今日 9 个合并 PR 中 6 个的真缺陷（attach 错挂、探针冻结、事件派发不可达、启动注入抑制、场景缓存陈旧、跨目标残留）全部只在这一层暴露。这条支出只增不减。

## 2. 闭环定义与缺口

**闭环**（每一步都有证据回流）：

```
一句话目标
  → 上下文装配（gather_task_context / 蓝图动词识别）
  → 计划（持久 DAG，证据门禁）
  → 构建原子化（蓝图代码生成 + 233 工具）
  → 行为验证（play_and_verify 步内断言，真机）
  → 质量评估（游戏感指标 / 视觉回归 / 性能预算 / 稳定性）   ← 缺
  → 打磨迭代（缺陷修复 + 手感/视觉调优 + 内容加深）          ← 缺
  → 跨目标回归（目标账本：新目标不破坏旧目标）               ← 缺
  → 交付（导出冒烟 + 发布包验证）                            ← 半缺
```

**缺口清单**（按闭环阶段）：

1. **测量缺口**：M2 评测未运行——首过成功率、错误完成声明率没有实测数字，所有后续投放缺乏罗盘。
2. **修改动词缺口**（E1-E4）：输入重映射、资产替换、UI 多分辨率、跨文件更名的目标层验证派生不存在（工具可组合，缺蓝图/演练）。
3. **恢复自动收口缺口**：journal 处方已附加但恢复语义未消费（崩溃慢测评审后接续）。
4. **优质维度缺口**：门禁止于"能玩"——游戏感（可测代理：加速度曲线、输入延迟帧、死亡/通关统计）、视觉质量（人工金标准 + 回归强制）、内容深度（敌人/关卡/进程/音效）、平衡性（完成时间/失败次数区间）均无门禁。
5. **组合规模缺口**：单场景单目标；多场景状态机（标题→玩法→胜负→重开）、跨目标项目账本、内容生成管线（generate_asset 等）未接入闭环。
6. **交付缺口**：导出冒烟存在；精确发布包 + 安装/回退验证不存在。

## 3. 阶段规划

> 每阶段给出：目标 / 交付 / 验收（可执行门禁）/ 算力投放重点。阶段间有依赖但不锁死日历；每阶段结束按实测修订后续优先级（M2 数据是罗盘）。

### P0 — 校准罗盘（先测量，再扩张）

**目标**：用真实代理运行把 M2 评测从"协议"变成"数据"，确立后续所有算力投放的依据。

**交付**：
1. 运行 3 项校准任务（N1/E4/R3）固定预算口径（模型侧 harness，协议在 `test/benchmarks/`）。
2. 首份对照报告（按 report_template）：分任务通过率、**错误完成声明数**、人工介入、工具调用、token、失败模式分类。
3. Oracle 自证（对故意损坏项目必须失败）——不过则本轮作废。
4. 按失败模式排序产出 top-3 修复清单，直接决定 P1/P2 内部排序。

**验收**：报告可由 JSONL 原始事件重算；每个数字有出处；不做胜负宣称（小样本方向判断）。

**算力投放**：校准 + 12×3×2 次正式对照（约 72 次代理运行）。这是全项目信息密度最高的支出之一——不设上限，跑满协议；防浪费靠"校准先行固定口径 + 失败样本全保留"。

### P1 — 修改闭环（E 类动词全证据化）

**目标**：四类修改目标（E1-E4）全部获得与 N 类同等强度的原生行为证据。

**交付**（每个都走完整新流程：蓝图/派生 + 单测 + 真机 E2E 场景 + 慢测收录）：
1. **E1 输入重映射**：派生演练 = 旧输入断言失效 + 新输入断言生效 + 其余输入回归（输入状态轮询，全部步内断言）。
2. **E2 资产替换**：派生门禁 = `scan_missing_resource_dependencies==0` + 运行时纹理尺寸/路径断言 + 既有行为（拾取/碰撞）不回归。
3. **E3 多分辨率 UI**：三视口尺寸（854×480 / 1280×720 / 1920×1080）逐档演练：按钮 `global_rect` 完全在视口内 + 相互不重叠 + 点击生效断言（需要视口尺寸控制的探针支持——先验证引擎侧 `window.size` 运行时可写性，不可写则用 `content_scale_factor`/场景内视口方案）。
4. **E4 跨文件更名**：F1+journal 已就位；补语义引用门禁（旧名零生产引用 + 注释/字符串保留原样的差异化断言）。

**验收**：durable flow 新增 4 个 E 场景全绿；每场景断言"演练=派生 + 行为断言通过"三重证据（对齐 pause/save 场景模式）。

**算力投放**：每片一次真机 E2E 全量回归（10→14 场景）；E3 的视口控制需实证探测（一次性高收益：若引擎路径不通早知道早转向）。

### P2 — 恢复闭环（R 类 + journal 自动收口）

**目标**：中断后的目标能诚实续跑——不丢人工修改、不重复副作用、不报假完成。

**交付**：
1. 评审 `test_game_goal_crash_*` 慢测对 `recovery_required` 的既有语义，然后实现 journal 自动收口：`complete_receipt` → 补回执收口；`re_prepare`/`resume` → 重置重放；`conflict` → 指名冲突停下。
2. R1-R4 oracle 形态的 E2E 场景：注入编译错误/缺失资源/回执丢失/手工修改，断言恢复路径各自到达正确终态。
3. `needs_input` 内容简报质量（沿用 goal-benefit 分支的思路在 main 重做，或认领该分支）。

**验收**：四个 R 场景在中断注入下全部诚实完成或诚实冲突；崩溃慢测更新后全绿。

**算力投放**：崩溃注入 E2E 是主要支出（每次注入一个完整 goal 流）；慢测在 CI 手动作业固化。

### P3 — 优质维度（从"能玩"到"好玩好看"）

**目标**：质量获得**可测代理 + 人工金标准锚点**，形成打磨迭代循环。

**交付**：
1. **游戏感门禁**：`play_and_verify` 已有 deterministic 采样/轨迹/逐标签指标（min/max/delta/peak）——新增 `feel_budget` 断言层（对齐 performance_budget 模式）：加速度曲线区间、输入→响应帧数上界、死亡到重生时长上界；蓝图暴露可统计计数（死亡数/通关时间）。
2. **视觉质量循环**：bootstrap → **人工批准金标准**（闭环中唯一的人类锚点，成本极低、频次极低）→ 此后每轮视觉回归强制执行；布局断言复用 E3 的边界检查。
3. **内容深度动词**：敌人巡逻+危险物+重生点、关卡分块（tilemap profile 深化）、分数→胜负状态机、音效事件挂接（audio bus 默认 + 事件触发断言）；**建议认领或重写 goal-benefit 分支的敌人/计分/射击动词与 119 条语料门禁**（在 `devin/concurrent-3d-blueprint-ledger`，需同步 234→当前计数）。
4. **打磨迭代模式**：goal 完成后进入迭代目标（"让跳跃更跟手"）——指标基线化 → 修改 → 指标对比 → 未达阈值继续；复用 durable DAG，不另起系统。
5. 收集/胜利动词按 #125 标准补齐行为断言（拾取后金币消失+分数变化+胜利标签出现的步内断言）。

**验收**：一个"参考垂直切片"目标集（移动+收集+暂停+存档+敌人+音效+视觉金标准）在迭代 3 轮内全部质量门禁通过；每项 feel/视觉门禁失败都能指出具体指标。

**算力投放**：**本阶段是算力大户，按哲学不设限**——迭代循环天然是重复运行（每轮修改→全量行为回归+指标采样）；防浪费靠：指标断言只在相关动词目标激活、轨迹采样仅 deterministic 模式、视觉回归用已有截图缓存、每轮迭代复用同一编辑器实例。人工金标准批准点控制在每个视觉里程碑一次。

### P4 — 规模与组合（从切片到完整游戏）

**目标**：多个一句话目标**累积成一个连贯游戏**，而不是各建各的。

**交付**：
1. **多场景状态机蓝图**：标题→玩法→暂停→胜负→重开；场景切换用运行时探针断言（current_scene 变迁 + 状态变量）。
2. **跨目标项目账本**：目标 B 完成后自动重跑目标 A 的语义套件（已有演练派生即套件）；账本记录每个目标的"拥有文件/输入/场景"，修改目标越界即冲突（与 journal/gather_task_context 对接）。
3. **内容生成管线接入**：`generate_asset`/`slice_sprite_sheet`/`inspect_gltf_asset` 进 profile，附带导入验证门禁（存在+尺寸+依赖零缺失）；3D 路线按 N4 扩展（认领 goal-benefit 的 3D 变体）。
4. **性能与稳定性长跑**：soak（长时间运行内存/帧率趋势，`get_runtime_memory_trend` 已有）+ 性能预算门禁纳入常规目标。

**验收**：一个 5+ 目标会话产出 3+ 场景连贯游戏，全部既有目标语义套件仍绿（回归账本生效）。

**算力投放**：长跑/soak 安排在分析间隙；多目标会话的回归账本复用 durable 回执（不重跑已证步骤）。

### P5 — 交付闭环（发布与回退）

**目标**：从"项目能玩"到"可分发产物可验证"。

**交付**：
1. 精确发布包（只含插件所需文件 + 版本/来源提交/清单/哈希；排除临时与用户配置）。
2. 安装/升级/回退验证（受控重启恢复；用户手改目录的冲突处理）。
3. `bump_version` + changelog 接入工作流收口；导出冒烟（`smoke_test_export` 已有）纳入交付门禁链。
4. （可选，另立决策）编辑器内热更新——仅在 P5 稳定且有真实升级摩擦数据后启动。

**验收**：从发布包安装→升级→回退全链在干净环境通过；慢测覆盖。

## 5. 风险与诚实边界

1. **优质无法全自动评定**：视觉/手感品味由人工金标准锚定（极低频）。不假装模型能自证"好看"。
2. **小样本评测只做方向判断**：72 次对照不支持"全面领先"宣称；每轮报告保留失败样本。
3. **蓝图有界性**：动词蓝图覆盖高频模式，不是通用代码生成；越界目标走通用工具路径 + AI 自主（由评测度量差距决定扩张方向）。
4. **并发 lane 资产**：goal-benefit 分支 4 提交（234 计数）待认领——认领需全库计数同步，重写则按 main 现状实现；二选一在 P3 前决策。
5. **环境抖动**（代理/网络/GitHub API）：已有一套绕行手册（直连推送、gh 备用、重试）；性能门禁在高负载本机偶发瞬态——以隔离复跑为准，不放宽阈值。

## 6. 立即可执行的前三步

1. **跑 P0 校准**（N1/E4/R3）：这是唯一还没被测量过的环节，也是后续一切投放的依据。产出首份报告后回来修订本规划优先级。
2. **P1-E3 视口可控性实证**（一次性探测）：真机验证运行时改窗口/视口尺寸的最可靠路径——它同时解锁 E3 门禁与 P3 布局断言，是当前性价比最高的未知项消除。
3. **P3 前置：认领/重写决策**（goal-benefit 分支）：决定动词语料与敌人/计分/3D 变体的来源，避免 P3 期间重复建设。
